# Apple 设计复审与第二轮改版

依据已安装的 [apple-design-skill](https://github.com/dickwu/apple-design-skill)。本项目是 React Web / PWA。HIG 在这里提供设计原则；浏览器控件、CSS 模糊、Lucide 图标不能等同于 UIKit、Liquid Glass 或 SF Symbols。

## 先纠正上一轮结论

上一轮把基础可读性改善与整体设计完成混在了一起。大幅宣传横幅、重复的四宫格、反复出现的品牌与口号，以及到处使用暖色，仍然压过真实内容。它改善了部分指标，但没有充分落实 Purpose、Simplicity、Familiarity、Craft，不能声称每项原则都已遵循。

此次重新审查了 12 份参考：accessibility、layout、typography、color、designing-for-ios、cross-platform、design-principles、branding、toolbars、lists-and-tables、tab-bars、icons。以下引文使用 skill 内对应文件与标题定位。现有弹窗的单面板与焦点恢复机制继续保留。

## 设计计划与落地

核心任务：先找到当前餐厅的一餐，再决定是否换个口味。以简洁的餐厅行、实际餐品与价格作为首页内容；口味盲盒和个人护照形成产品特色。参考熟悉的 iOS 工具型应用组织方式，视觉是否“像苹果”仍然是设计判断，不能由一份合规清单证明。

- 移除宣传横幅、重复的四宫格和额外品牌栏。`branding.md › Best practices`：“Ensure branding always defers to content.”
- 顶部常驻明确的演示 / 真实连接状态、餐袋与设置。五个文字标签导航保留，手机底部、宽屏侧栏。`tab-bars.md › Best practices`：“Use a tab bar to support navigation, not to provide actions.”
- 钱包从四个独立小卡片改为带分隔线和披露箭头的分组列表，活动也使用列表。`lists-and-tables.md › Content`：“Keep item text succinct”。
- 实色内容面、轻量导航材质、统一圆角和间距；蓝色只承担操作与选择状态，食物照片保留内容色彩。`color.md › Best practices`：“Avoid using the same color to mean different things.”
- 统一大标题、节标题、正文和说明层级，保持系统字体与 rem。`typography.md › Conveying hierarchy` 要求通过大小、字重、颜色传达层级。
- 灵感筛选与护照分段选择显式提供 `aria-pressed`；保留普通按钮、键盘入口、Escape、焦点返回与减少动效支持。

手机结构：

```text
连接模式                     餐袋 / 设置
日期
发现
当前餐厅                          >
今天吃什么                 全部菜单 >
真实餐品照片 / 名称 / 参考价         >
换个口味                记住这一口
更多餐品
活动与体验：日历 / 抽奖 / 派对
发现     点餐     灵感     钱包     护照
```

宽屏保留相同内容顺序，以侧栏替代底部导航，餐品网格扩展到四列。大字号下两列内容重排为一列，工具栏随内容增高。短暂盲盒与转盘动效承载揭晓反馈，减少动态偏好下取消非必要运动。

自我批评：中性分组列表和蓝色控件可以用于很多应用，这是有意采用熟悉的工具外壳；辨识度来自实际餐品、心情与预算餐选、手动味觉记录，而不是给每个控件加品牌装饰。首屏餐选点击直接打开餐品详情，避免只有宣传功能的主视觉。

## 八项原则逐条复核

依据 `design-principles.md` 同名标题。这里记录证据与边界，不设置“全部通过”认证。

| 原则                | 此轮证据                                                             | 判断与剩余边界                                              |
| ------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------- |
| Purpose 目的        | 首屏先给当前餐厅、餐品与价格，直接进入详情                           | 比上一轮更聚焦；餐选目前是固定经典优先，并非个性化模型      |
| Agency 自主         | 五区自由切换；预览可取消；取消后保留取餐选择；面板返回恢复焦点       | 已验证典型路径，未穷尽全部错误恢复分支                      |
| Responsibility 责任 | 工具栏明确演示数据；真实订单仍需重新核价和逐次确认；本地记录说明保留 | 此轮只操作演示流程，无真实权益或支付调用                    |
| Familiarity 熟悉感  | 分组列表、披露箭头、大标题、底部导航、分段选择、一致图标             | 更接近 iOS 常见组织；仍是 Web 控件和线性图标，不是原生组件  |
| Flexibility 灵活    | 360/390 手机、1440 桌面、200% 字号、明暗外观检查                     | 未做 iPhone 真机 VoiceOver、原生 Dynamic Type、全部设备测试 |
| Simplicity 简洁     | 移除重复品牌、营销横幅、重复入口；次要活动归组                       | 功能仍多，后续可根据实际使用频率继续收敛                    |
| Craft 打磨          | 修正选中态文字不可见与大字号工具栏重叠；统一颜色、间距和控件         | 经过截图和交互迭代；没有宣称达到所有 HIG 细则               |
| Delight 愉悦        | 保留免费口味盲盒、转盘、护照、印章、分享与时间胶囊                   | 符合轻松尝鲜方向；愉悦感尚无用户研究结论                    |

## 色彩与字体

| 语义角色 | 浅色      | 深色      | 与内容面的文字对比度（浅 / 深） |
| -------- | --------- | --------- | ------------------------------- |
| 背景     | `#f2f2f7` | `#000000` | 非文字                          |
| 内容面   | `#ffffff` | `#1c1c1e` | 非文字                          |
| 主文字   | `#1c1c1e` | `#f5f5f7` | 17.01:1 / 15.63:1               |
| 辅助文字 | `#626268` | `#aeaeb2` | 6.06:1 / 7.69:1                 |
| 操作     | `#0066cc` | `#78b8ff` | 5.57:1 / 8.18:1                 |
| 成功状态 | `#257044` | `#8bd5a0` | 同时显示文字，非单靠颜色        |

按源代码十六进制颜色计算 WCAG 相对亮度比，非截图估算。辅助文字在浅灰背景为 5.43:1。半透明导航在减少透明度偏好下回退到实色。正文 17px、大标题 34px、节标题约 21–22px、说明 13px，最小数据标记约 12px；均由 rem 定义。CSS px 不能保证等同原生 pt。

## 本轮实测（2026-11-02）

- 五个主页面在 390px 宽度下文档宽度均为 390px；可见按钮未发现宽或高小于 28px。主要图标按钮保留 44px 命中区。
- 五个主页面在 360px / 根字号 34px（200%）下文档宽度均为 360px。首次检查发现工具栏重叠，修复后工具栏底部与正文顶部同为约 146.5px；已截图复查。
- 390×844 浅色 / 深色首页、钱包、护照、灵感与点餐均检查过实际页面；1440×1000 桌面首页无横向溢出。
- 盲盒生成成功，并明确不自动装袋。演示餐品 → 加入餐袋 → 核价 ¥25.50 → 订单预览 → 取消，返回保留“打包带走”。同时仅存在一个打开的 dialog。未确认创建订单；测试加入的餐品已移除。
- 使用 Enter 打开餐厅选择，Escape 关闭，焦点回到原餐厅按钮。
- `npm run check`：48 项业务 / 安全测试、TypeScript、Vite 生产构建。UI 视觉判断主要来自浏览器检查，48 项测试不等于视觉合规测试。

仍需真实 iPhone / VoiceOver、系统字号与系统手势验证；Web 模糊不是原生 Liquid Glass。不能保证每条 HIG 全部满足，也不把“安装了 skill”当作 Apple 设计认证。
